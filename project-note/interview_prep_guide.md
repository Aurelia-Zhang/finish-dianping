# 黑马点评项目 — 大厂面试备战指南

## 一、面试官的追问逻辑（必须先理解）

大厂面试官**不是随机提问**，他们的深挖路径是：

```
你说的方案 → 为什么选这个？ → 有什么问题？ → 怎么解决？ → 还有更好的方案吗？
```

所以你的应对策略是：**每个技术点，都准备好"我选了什么 → 为什么 → 缺点是什么 → 替代方案"这条链路。** 面试官最怕的候选人不是答不上来的，而是"什么都知道一点但说不深"的。你把一个点吃透了，比啥都会但都说不清强一百倍。

---

## 二、30 秒开场话术（背熟）

> "这个项目是基于 Spring Boot + Redis 的本地生活服务平台，类似大众点评。我主要负责的核心模块有两个：**商户缓存**和**优惠券秒杀**。
>
> 商户缓存这块，我针对缓存穿透、击穿等问题分别做了处理，封装了一个通用的缓存工具类。
>
> 秒杀这块，我用 Lua 脚本做原子性校验，配合 RabbitMQ 异步解耦，实现了高并发下的库存一致性和一人一单保障。"

**注意**：开场不要说太多，30 秒讲完让面试官来追问。说太多反而暴露弱点。

## 三、五大核心模块的深挖准备

### 模块 1️⃣：商户缓存（最可能第一个被问）

#### 面试官大概率的追问链路：

```
"缓存了什么？" → "为什么要缓存？"
     ↓
"缓存会有什么问题？"        ← 你主动说三个：穿透、击穿、一致性
     ↓
 穿透怎么解决？ ──→ 缓存空值 ──→ "还有别的方案吗？" ──→ 布隆过滤器
     ↓
 击穿怎么解决？ ──→ 互斥锁 / 逻辑过期 ──→ "两者怎么选？"
     ↓
 一致性怎么保证？ ──→ 先更新DB再删缓存 ──→ "有并发问题吗？" ──→ 延迟双删/Canal
```

#### 你需要背熟的回答要点：

**缓存穿透**：
- 我实现了两种方案：缓存空值 和 布隆过滤器，可以通过配置切换
- 缓存空值：简单直接，但会占用 Redis 内存存储大量无效 key
- 布隆过滤器（Redisson RBloomFilter）：内存极省（1 万数据约 12KB），但有约 1% 误判率，且无法删除元素
- **面试加分**：两者可以结合使用——布隆过滤器拦截大部分无效请求，缓存空值兜底处理布隆过滤器的误判

**缓存击穿**：
- 互斥锁：保证一致性，但牺牲可用性（其他线程要等）
- 逻辑过期：保证可用性（返回旧数据），但牺牲短暂一致性
- **面试必问**："怎么选？" → 看业务。金融数据用互斥锁，热门商铺详情用逻辑过期

**数据一致性**：
- 先更新 DB，再删缓存（Cache Aside Pattern）
- **被追问并发安全时**：承认极端场景下有问题，然后说延迟双删、Canal 监听 binlog 等补偿方案

### 模块 2️⃣：优惠券秒杀（被深挖最深的模块）

#### 面试官大概率的追问链路：

```
"秒杀流程说一下" → 你画出完整链路
     ↓
"超卖怎么解决？" ──→ Lua 原子操作 ──→ "为什么用 Lua？" ──→ Redis 单线程 + 原子性
     ↓
"一人一单？" ──→ Redis Set + 分布式锁 ──→ "为什么不用 synchronized？"
                                              ──→ 集群模式下不同 JVM 锁不住
     ↓
"异步下单？" ──→ RabbitMQ ──→ "为什么不用 Kafka？" / "消息丢失怎么办？"
     ↓
"分布式锁？" ──→ Redisson ──→ "WatchDog？" / "RedLock？" / "对比 ZooKeeper？"
     ↓
"全局 ID？" ──→ Redis 自增 ──→ "对比雪花算法？"
```

#### 你需要背熟的回答要点：

**秒杀流程（必须能画出来）**：
```
用户请求 → Lua脚本（Redis 内原子操作）
             ├─ 判断库存（GET）
             ├─ 判断是否重复（SISMEMBER）
             ├─ 扣库存（INCRBY -1）
             ├─ 记录用户（SADD）
             └─ 发消息（XADD / RabbitMQ）
                    ↓
             消息队列（异步）
                    ↓
             消费者 → 获取分布式锁 → 数据库校验 → 扣库存 → 创建订单
```

**为什么用 Lua？**
> "Redis 执行 Lua 脚本是原子性的——因为 Redis 是单线程执行命令的，Lua 脚本在执行期间不会被其他命令打断。在我的场景里，库存判断、扣减、用户记录这些操作必须是原子的，否则在高并发下两个请求可能同时读到库存 = 1，都成功扣减，造成超卖。"

**Lua 脚本的限制（面试官爱问的冷知识）**：
- 不能执行太久（默认 5 秒超时），否则阻塞 Redis
- Cluster 模式下，所有 key 必须在同一个 slot（用 hash tag 解决）
- 脚本中不能有随机性操作（影响主从复制）

**RabbitMQ vs Kafka**（如果面试官问为什么不用 Kafka）：
> "在我这个场景里，消息量级不大，RabbitMQ 更合适。RabbitMQ 的优势是路由机制灵活（exchange + routing key）、有死信队列、消息确认机制完善。Kafka 更适合日志收集、大数据流处理这种超高吞吐场景。"

**消息丢失怎么办**（必问！）：
- 生产端：开启 Publisher Confirm（确认模式），消息到达交换机后回调确认
- 队列端：队列和消息都设置为持久化（durable）
- 消费端：手动 ACK（代码里已经用了 `acknowledge-mode: manual`）
- 兜底：对账系统，定时比对 Redis 已扣减库存和数据库实际订单数

### 模块 3️⃣：分布式锁（面试官最爱的 Java 八股结合点）

#### 你需要背熟的演进路线：

```
synchronized → SimpleRedisLock(SETNX) → Redisson
     ↓                    ↓                   ↓
  仅单机有效         不可重入/无续期      可重入+WatchDog+Pub/Sub
```

**synchronized 为什么不行？**
> "在集群部署（多个 JVM 实例）下，synchronized 只能锁单台机器内的线程，不同机器之间无法互斥。"

**SimpleRedisLock 有什么问题？**
- 不可重入（同一线程二次获取锁会死锁）
- 无自动续期（业务超时后锁自动释放，其他线程可能闯入）
- 解锁时需要 Lua 保证"判断+删除"原子性

**Redisson 怎么实现可重入？**
> "底层用 Redis Hash 结构：key 是锁名，field 是线程标识，value 是重入次数。每次加锁 value + 1，解锁 value - 1，减到 0 时删除 key。"

**WatchDog 机制**：
> "默认 30 秒过期，加锁成功后 WatchDog 每 10 秒（1/3 TTL）自动续期。**只有不指定 leaseTime 时 WatchDog 才生效**——这是个常考冷知识。"

---

### 模块 4️⃣：登录态（ThreadLocal + 分布式 Session）

**为什么用双拦截器**：一定要能解释清楚，核心是"即使访问公开页面也能刷新 Token"。

**ThreadLocal 内存泄漏**：
> "Entry 的 key 是弱引用，会被 GC 回收变成 null，但 value 还在。必须在 afterCompletion 里 remove，否则线程池复用线程时会泄漏。"

---

### 模块 5️⃣：点赞 + Feed 流（选择性准备）

如果面试官问到，核心讲：
- 用 **ZSet** 做点赞，score 是时间戳，实现按时间排序 + 唯一性
- Feed 流用推模式，大 V 场景需要改推拉结合
- 滚动分页用 `ZREVRANGEBYSCORE` + offset，避免传统分页的跳页问题

## 四、面试中最容易踩的坑

### ❌ 坑 1：简历上写了 RabbitMQ，问你源码你说不清

**应对**：不需要背 RabbitMQ 源码，但你必须能回答：
- RabbitMQ 有哪几种交换机？（Direct、Fanout、Topic、Headers）
- 消息确认机制是什么？（Publisher Confirm + Consumer Ack）
- 如何保证消息不丢失？（上面已经总结了三端保证）
- 什么是死信队列？（消息被拒绝/超时/队列满时进入 DLX）

### ❌ 坑 2：被问"你怎么测的？QPS 多少？"

**应对**：
> "我用 JMeter 做了并发测试，模拟了 200 个并发用户同时秒杀。在有 Lua 脚本 + 异步队列的架构下，接口响应时间从同步方案的 500ms+ 降到 20ms 以内，同时没有出现超卖。"
> （不需要说具体 QPS 数字，因为这取决于机器配置，但要说出"做过测试"和"有什么效果"）

### ❌ 坑 3：被问到你没准备的知识（比如 Redis 底层数据结构）

**应对**：不要慌，坦诚说：
> "这个我了解一些但不深入，我知道 ZSet 底层是跳表，String 底层是 SDS……（说你知道的）。这块我还在学习中。"
> 
> 坦诚比瞎编强 100 倍。

## 六、面试节奏控制技巧

1. **主动给钩子**：回答完一个问题后，故意提一嘴下一个方向。比如回答完缓存穿透后说"除了穿透，缓存击穿那块我也做了两种方案……"，面试官大概率顺着你的钩子问。
2. **不会的就说不会**：大厂面试官不期望你什么都会，但他们讨厌你瞎编。
3. **用"对比"展示深度**：不要只说"我用了 Redisson"，要说"我对比了 synchronized、手写 SETNX、Redisson 三种方案，最终选了 Redisson 因为……"，这样展示思考过程。
4. **适当暴露"改进点"**：主动说"如果让我重新做，我可能会加上 Canal 做最终一致性"，让面试官觉得你有反思能力。
